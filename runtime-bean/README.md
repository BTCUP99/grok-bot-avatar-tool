# 头像工具维护说明 · 1.4.3

用户入口与首次配置见根目录 README.md。工具包含 42 款选择：31 款原生动态角色和 11 款写真轻动效头像。统一入口为 `启动头像工具.command`；任意 Bot 的“对话详情 → 点击头像”提供“原创动态头像 / 写真头像 / 官方选项”三个标签，每个 Bot 独立保存。

## 运行原理

启动器正常启动用户自行安装的官方 Grok Bot 0.78.4、0.78.5 或 0.79.4，通过仅监听本机的 CDP 调试连接，按精确路径接管两个已核验的本地 JavaScript 加载请求。局部适配后的内容仅在内存中返回；不写回 `.app`、不重新签名、不分发完整厂商代码。

头像选择窗口扩展了每个独立 Bot 的原生编辑入口，包含动态角色、写真头像与官方选项；群组保持官方编辑器。选择以 `{Bot ID: 款式键}` 写入本工具的 `config.local.json`（`version: 2`，自动迁移 1.2.0 的 `botId/shape`）；官方编辑器继续接收原始账号数据。未选择的 Bot 保持原样。工具不是官方插件，也不把自定义角色注册到云端。

多 Bot 的实现要点：

- 本机分配表保存全部 42 款选择；原生形状查询只返回原生角色键，写真键不进入官方几何解析。图片分类和静态图来源分别处理写真。
- 知道自身 Bot 的五个原生组件（头像、角色、标记、侧边栏与详情）由 `avatarBound` 包裹：订阅该 Bot 的分配变化，并通过 React Context 把 Bot ID 交给其下的头像显示函数。
- 头像显示函数的包装层按已绑定的 Bot 和当前渲染用途选择原生引擎或照片组件；官方形状网格仍走原生路径，状态取该 Bot 自己的活动。
- 原生播放器 `p_` 把自身的 `state` 交给引擎（`avatarState`），每个 Bot 的工作灯互不干扰。照片组件按 Bot 共享指针与完成信号，避免侧边栏、详情和隐藏来源重复触发同一次轻弹。
- 加载器校验页面发来的 `(Bot ID, 角色|null)`，写入配置并重新烘焙内存模块，渲染层重载后仍保持全部选择。

31 款动态角色的 gaze、pointer、表情、姿态平滑、投影、状态控制器与可见性节流继续由官方引擎负责。系统将窗口判定为隐藏时，原生动画会暂停；实际验收必须在可见窗口进行。

写真通过独立组件呈现同一张裁切照片，沿用原有指针输入与每 Bot 活动来源；图片自身没有眨眼、嘴型、变脸或新视角生成。整张卡片的闲置角度为 X +6° / Y −10° / Z −6°，缩放 1；悬停中心为 0° / 0° / 0°，缩放 1，沿指针移动的 X/Y 倾角限制为 ±6°。工作柔光周期为 1.6 秒，完成轻弹为 640 ms，同一完成标识只触发一次。系统“减少动态效果”偏好会停用倾斜过渡、循环柔光和轻弹动画。参数以 `photo-runtime.js` 为准，属于照片卡片动效，不套用原生角色的四元数验收值。

1.4.2 新增 Grok Bot 0.79.4 适配，保留 0.78.4 / 0.78.5 分支。更新了新版的头像组件、选图入口、React 与材质函数绑定；42 款素材和已有的每 Bot 选择继续沿用。升级本工具时无需重建头像或重新选择。

## 开发入口

```bash
npm test
node runtime-bean/tool.mjs --audit --demo
node runtime-bean/spec.mjs --shape robot_cloudwhale
node runtime-bean/generate-library.mjs
# PNG 栅格化是开发步骤，需要可选的 @resvg/resvg-js
RESVG_MODULE=/path/to/resvg/index.js node runtime-bean/render-library.mjs
npm run prepare:runtime
npm run package
```

`--demo` 提供明确标记的工作与完成外观演示，不发送消息、不运行 Bot 任务；`--audit` 只观察真实指针和当前渲染节点。普通用户模式不显示这两个面板。

## 造型和规格

- `../avatar-designs/catalog-shapes.js`：原十款造型、实体注册和曲面渲染工具。
- `../avatar-designs/fantasy-shapes.js`：12–31 号奇想新作的独立几何与装饰。
- `library.mjs`：31 款原生角色的公开名称、键、灯位与灯色；键前缀 `robot_` 仅用于内部兼容，不限制题材。
- `avatar-catalog.mjs`：42 款可选清单，包含 11 款写真素材文件、256 × 256 尺寸与 SHA-256 校验。
- `photos/`：11 张近景 PNG；`framing.json` 记录原片裁切框与脸宽比例。
- `photo-runtime.js`：整张照片的轻微倾斜、工作柔光、完成轻弹、每 Bot 指针共享与完成去重。
- `library-runtime.js` / `neon-shape.js`：原生材质、工作灯和形变回退。
- `config.mjs`：本机配置读写、迁移与校验。
- `library-state.mjs` / `library-bridge.js`：按 Bot 的本机选择、实际状态订阅、Bot Context 与完成去重。
- `library-picker.js`：原生编辑入口、动态/写真/官方三个标签、搜索、分组、暂存、应用、恢复原头像与取消。
- `spec.mjs`：精确参数、六姿态 SVG 与 36 / 64 尺寸参考。
- `头像制作规范.md`：共用制作和验收规则；`头像库使用说明.md`：角色清单与验证范围。

新增原生角色需同步形状注册、库清单、缩略图、四状态素材、规格快照与白名单包。图片生成阶段可关闭离线构建的缩略图嵌入，以解决资产首次生成的依赖顺序；实际启动始终读取完整缩略图。写真使用独立清单与经过尺寸、哈希校验的 PNG，不加入原生几何回归。变更照片裁切时需更新该项素材哈希，并重新检查小尺寸及实际窗口效果。

## 恢复、兼容与公开包

Command-Q 完全退出，再从官方图标打开，即恢复原来的头像。下次使用本工具入口会恢复记住的本机选择。仅关闭外部加载器不能立即撤销已加载的内存适配，也不能代替完整退出。

支持 macOS Apple Silicon 上按版本固定的 0.78.4、0.78.5 与 0.79.4。版本、官方签名、ASAR 完整性、整包和输入脚本哈希均受检查；升级后重新读源码、适配、测试和进行真实窗口验收，不得放宽检查强行运行。

调试端口只监听 `127.0.0.1:19223`，没有身份认证，同一设备其他进程可能访问；不要转发端口。普通官方入口重开后端口关闭。

`package-library.mjs` 使用显式白名单输出用户包与源码包。配置、证据、聊天截图、个人 ID、厂商代码和历史材料不进入公开包。完整包自带通过哈希和签名校验的官方 Node.js，并保留其许可；源码包不带二进制。11 款人物素材由维护者自行生成，为非真人虚拟人物图像，随本项目按 MIT 许可公开；见 `photos/README.md`。发布流程见 `../docs/RELEASING.md`。

1.4.2 已在通过签名校验的 0.79.4 上完成全套 `npm test`，并用该版本的官方 React、头像组件、样式与选图编辑器进行独立窗口验证：42 项选择可用，两个合成 Bot 的选择、取消和恢复互不影响；11 款写真在 36 / 64 CSS px 完成 44 次转正与回位观测；31 款动态角色在两个尺寸均正常渲染；工作柔光、完成轻弹及完成去重通过。当前账号的 Bot 窗口保持运行，未被重启；此次状态验证使用合成数据，未发送真实任务。0.78.4 / 0.78.5 兼容分支保留，本轮未重新运行旧客户端。

1.4.0 已完成全部 11 款写真在实际侧边栏 36 × 36 和详情 64 × 64 的鼠标悬停转正/移开回位检查，共 44 次姿态观测；实际加载图像均为对应固定哈希的 256 × 256 PNG。香氛街区和湖畔咖啡通过本机工作柔光、完成轻弹演示。恢复原头像、另一 Bot 的 11 款写真入口与取消、像素小子的两处原生转正/回位也已检查。本机状态演示不代表真实任务端到端完成；正常官方启动已恢复原头像并关闭调试端口；工具重启已恢复所选写真。最终官方 0.78.4 整包哈希未变，签名验证通过。完整验收范围见 `头像库使用说明.md`。
