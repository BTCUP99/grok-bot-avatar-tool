# 自定义头像：制作、尺寸与转向规范

当前共 31 款：原十款、霓虹夜行与二十款奇想新作。新增角色的几何源为 `../avatar-designs/fantasy-shapes.js`，逐款设计理由见 `../avatar-designs/奇想新作设计说明.md`。共用本规范的几何、指针、表情与验收要求；角色参数和状态响应见 [头像库使用说明](头像库使用说明.md) 与 `library/manifest.json`。catalog 角色执行 `node spec.mjs --shape robot_角色键` 重建，例如 `--shape robot_titan`；离线输出在 `library/specs/`。当前原生状态灯和完成响应由共用库实现，不改写下文的 `bean-shape.js` 基准。

霓虹夜行复用奶糖几何并增加材质、状态灯和完成响应，独立参数与窗口验收范围见 [霓虹夜行说明](霓虹夜行说明.md)。执行 `node spec.mjs --shape neonNight` 重建其参数快照与规格图；原生视线、悬停、回位和表情引擎的共用要求继续适用。

本文主体保留杏橙豆团的复刻基准。2026-11-04 新增已接入的奶糖喵机，独立参数以 [milkcat-shape.js](milkcat-shape.js) 和 [奶糖喵机说明](奶糖喵机说明.md) 为准；共用下文的显示尺寸、原生指针映射、转向和验收规则。运行 `node spec.mjs --shape milkcat` 重建 [奶糖喵机参数快照](奶糖喵机参数快照.json) 与 [奶糖喵机规格图](奶糖喵机规格图.svg)。不加参数仍重建原豆团。

基准：2026-11-04，macOS Apple Silicon，Grok Bot 0.78.4。本文描述**本项目当前可复刻的实现**，不是官方公布的自定义头像导入格式。参数以 [bean-shape.js](bean-shape.js) 为准；引擎数值由 [spec.mjs](spec.mjs) 从通过版本、哈希和签名校验的本机客户端离线测量。

## 交付物与复刻入口

当前头像是程序化的实体轮廓、贴附在曲面上的双眼和装饰，以及原生姿态引擎。不需要制作六张角度图片或循环动画。以下六个姿态用于检查外观，实际转向是连续的。

- [头像规格图.svg](头像规格图.svg)：原生引擎离线渲染的闲置、正面、左右、上下，以及 36 / 64 尺寸参考。
- [头像参数快照.json](头像参数快照.json)：完整四元数、欧拉角、缩放、位移和源码哈希。
- [验证摘要](library/verification.json)：离线规格与实际窗口验收的范围。真实窗口截图仅保留在本机 `evidence/`，不进入公开包。

复刻现有豆团：完整保留本目录，按 [使用教程](README.md) 启动，并选择本机目标 Bot。复制 `bean-shape.js` 本身只能保留造型，还需要 `patch.mjs` 的注册和显示分支适配，以及加载器提供接入。

## 一、造型和坐标

设计语言：一个不对称、圆润的杏橙豆团，两只深棕色长圆眼，少量眼内高光和腮红。无嘴、无鼻子、无四肢。根目录 `assets/杏橙豆团概念参考.png` 是仅在本机项目保留的设计参考，运行时不会加载这张图片，公开包无需包含它。

形状键固定为 `apricotBean`。身体路径为：

```text
M43 100 C54 90 77 91 85 72 C86 39 112 13 144 15
C183 16 211 50 214 92 C220 133 197 171 166 194
C128 221 77 224 42 197 C9 172 13 125 43 100 Z
```

这是闭合 SVG 路径的设计坐标，**不是最终显示像素或上传图片尺寸**。原生路径预处理后，由 `Fc` 构造实体球集合，`xc` 创建曲面贴附座，身体、眼睛、腮红随同一个姿态投影。当前离线得到 47 个球；数量是该版本引擎采样的结果，不是手工制作数量要求。

| 配置 | 当前值 | 含义 |
| --- | --- | --- |
| `cc.apricotBean().size` | `1.25` | 原生形体比例系数，不是 CSS 尺寸 |
| silhouette | `kind: 'solid'` | 用原生实体投影生成侧面与正面轮廓 |
| `samples` / `balls` | `[]` / `Fc('apricotBean')` | 轮廓由球集合生成 |
| `isLoop` / `yawPeriod` | `false` / `null` | 保留非循环轮廓与原生转向处理 |
| seat | `xc('apricotBean', balls)` | 眼睛和腮红使用相同曲面 |
| 默认静止 `frame.zoom` | `0.6` | 当前引擎静止基准；工作动作可能改变它 |

修改轮廓后必须重新检查转向中的轮廓、远侧眼睛和腮红遮挡。不要直接把原 PNG 旋转后当成实体转头，也不要固定画两只始终朝前的眼睛。

## 二、尺寸规范

| 层级 | 当前值 | 解释 |
| --- | --- | --- |
| 侧边栏实际头像容器 | **36 × 36 CSS px** | 来自真实窗口验收的 `avatarRect` |
| 详情实际头像容器 | **64 × 64 CSS px** | 来自真实窗口验收的 `avatarRect` |
| 共享角色源分辨率 | **192** | 当前客户端 `hT` 的共享源 `resolution`，不是上传要求 |
| 离线回归输出 | **96 × 96 SVG 单位** | `verify.mjs` 的测试尺寸，可以与显示尺寸不同 |
| 制作对照大图 | **192 × 192 SVG 单位 / 每姿态** | `spec.mjs` 生成；SVG 可缩放 |

SVG 根 `viewBox` 为 `0 0 size size`。内部精度由原生渲染器按尺寸和缩放计算，最少为 144；因此不要把某次内部 sprite 尺寸硬编码成素材规格。Retina 截图的物理像素数也不等于 CSS px。

当前方案不使用图片上传、序列帧或透明 PNG，所以没有“必须交付 256×256 GIF”的要求。制作新造型时，必须在 **36 / 64** 两种实际显示尺寸检查辨识度，并观察原生 idle / hover 的留白和轮廓裁切；不能只检查放大的设计稿。上述界面尺寸属于当前窗口实测，未来 UI 更新后需重测。

## 三、眼睛、腮红和配色

眼睛布局对象：

```js
Oo.apricotBean = { width: 0.258, height: 0.48, gap: 0.49, shiftY: 0.035 };
```

这些是原生眼睛布局参数，基于引擎局部空间和表情轮廓计算，**不能直接解释为头像宽高的百分比或固定像素**。原生布局函数会按表情分支处理宽高、间距和位移。复刻时先原样保留；不要另画静态眼睛覆盖其上。`shiftY` 在此曲面座中用于向下偏移贴附中心。

| 部件 | 精确参数 |
| --- | --- |
| 眼睛颜色 | `#3c2924`，`cutout: false`，使用实色眼睛 |
| 身体径向渐变中心 / 半径 | `(0.36r, 0.28r)` / `0.65r`，`r` 是当前内部 sprite 尺寸 |
| 渐变色标 | `0: #ffe2ae`；`0.43: #ffc180`；`0.79: #f4a260`；`1: #dc8347` |
| 腮红局部中心 | 左 `(-0.40, -0.24)`；右 `(0.40, -0.24)` |
| 腮红椭圆半径 | `rx: 0.115`，`ry: 0.06`；每圈 40 个采样点 |
| 腮红颜色 / 透明度 | `#e67b65` / `0.38` |
| 腮红贴附 | `tl(dc('apricotBean'), jp(frame, size), r, ...)`，`shiftY: 0.035` |
| 眼内高光 | `#fff8e9`，透明度 `0.9` |

高光按**投影后每只眼睛**的包围盒计算：左上角 `(x0,y0)`、宽高 `(w,h)`，高光中心为 `(x0 + 0.36w, y0 + 0.25h)`，半径为 `rx = 0.16w`、`ry = min(0.20w, 0.12h)`。每只眼睛独立 `clipPath`，眨眼时高光随眼睑裁切；腮红和高光外层再受身体轮廓裁切。SVG ID 必须沿用每次渲染传入的唯一 `id`，避免多头像之间串用遮罩。

## 四、转向规范

四元数顺序为 **`[w,x,y,z]`**。下表角度来自静止引擎稳定后的四元数，采用该引擎自身的欧拉角分解，组合顺序 `Rz(roll) · Ry(yaw) · Rx(pitch)`。不要直接拿其他 3D 工具默认的旋转顺序套用。

| 检查姿态 | 输入 `setGaze` | yaw 左右 | pitch 俯仰 | roll 倾头 |
| --- | --- | ---: | ---: | ---: |
| 闲置 / 移开回位 | `null` | `+33.293156°` | `−15.896271°` | `+25.384801°` |
| 悬停中心正面 | `[0,0]` | `0°` | `0°` | `0°` |
| 看左 | `[-1,0]` | `−26°` | `0°` | `0°` |
| 看右 | `[1,0]` | `+26°` | `0°` | `0°` |
| 看上 | `[0,1]` | `0°` | `−19°` | `0°` |
| 看下 | `[0,-1]` | `0°` | `+19°` | `0°` |

闲置是一个复合倾斜姿态，并非单独绕竖轴“侧转 30°”。真正复刻时以四元数为准：

```text
闲置：[0.9169956148992757, -0.19158116627165409,
       0.2476740623943209,  0.2471300422906653]
正面：[1, 0, 0, 0]
```

原生 SVG 投影会按尺寸量化角度，因此大图看起来可能使用邻近的离散角度；这不改变引擎连续的目标姿态。验收面板中的 `data-pose` 保留五位小数，闲置应为 `0.91700,-0.19158,0.24767,0.24713`，正面应为 `1.00000,0.00000,0.00000,0.00000`。

### 鼠标坐标和过渡

当前客户端 `pT` 监听容器的 `pointermove` / `pointerleave`，取 `.sand-grok-bot-mark` 的矩形。令头像中心为 `(cx,cy)`、宽度为 `W`，输入为：

```text
gx = clamp((mouseX − cx) / (max(W,1) × 0.5), −1, 1)
gy = clamp(−(mouseY − cy) / (max(W,1) × 0.5), −1, 1)
```

中心是 `[0,0]`；右方 `gx > 0`，上方 `gy > 0`。当前头像是正方形，X/Y 都按宽度归一化。监听范围由宿主容器决定，可能大于头像本身；离开监听容器才传入 `null`。不要把“移出头像图片边界”写成所有页面都完全相同的事件边界。

在静止、没有其他工作动作叠加时，稳定目标为 `yaw = 26gx`、`pitch = −19gy`、`roll = 0`，原生位移为 `[0.07gx, 0.055gy]`。工作动画可能叠加动作，这张表不是所有 Bot 状态的姿态上限。

过渡沿用原生平滑系数 `alpha(dt) = 1 − 0.86^(dt / (1/60))`，并带接近目标时的吸附阈值。没有另外规定固定 300 ms 的 CSS 动画，也没有悬停后自动回位的计时器。鼠标不动时保持朝向，离开后恢复基准。原生眨眼和表情保留；本方案没有额外添加常驻呼吸循环或独立眨眼定时器。

## 五、重建与验收

在本目录运行：

```bash
node spec.mjs
node verify.mjs
```

第一条重新输出六姿态规格图和参数快照，只读官方安装包、在内存中运行渲染器，不连接正在运行的 App。它还校验 36 / 64 尺寸下的指针坐标映射及转正回位。第二条完成原生回位循环、25 种旧形状共 75 组姿态对比、眨眼和异常输入检查。

修改或新增造型时，按以下流程维护：

1. 修改 `bean-shape.js` 的路径、形体、眼睛、装饰；需要新形状键时，同步 `patch.mjs` 的渲染分支与目标 Bot 显示适配。
2. 重建规格图，核对六姿态、36 / 64 尺寸、眼睛遮挡和眨眼高光。四个斜向 `[±1,±1]` 也应检查穿帮和裁切；它们由连续模型组合得到，无需独立素材。
3. 通过离线回归后，在明确选定的 Bot 上实测。侧边栏和详情分别悬停中心保持、移开回位，并重复。离线结果不能代替窗口验收。
4. 用可选 `--audit` 读取真实事件，确认保持时 `trusted: true`、`buttons: 0`，正面和回位姿态匹配。
5. 检查正常退出重开恢复原头像、经启动器重开再生效，且官方签名与 ASAR 哈希保持原样。
6. 更新本文、参数快照、效果图、版本说明和公开包清单。客户端升级后先检查私有接口变化，不能只放宽版本或哈希校验。

当前已完成的真实窗口证据：侧边栏与详情中心转正、移开回位；详情正面两次采样相隔 15.355 秒；正常重开恢复、加载器重开再生效。原生事件和截图在本机 `evidence/`，不进入公开包。左右上下角度及六姿态规格图属于离线引擎测量，没有冒充新的 App 内实测。

## 写真轻动效头像（1.4.0 新增）

11 款写真使用原图裁切的 256 × 256 PNG，在 36 / 64 CSS px 容器显示；每张内容哈希固定在 `avatar-catalog.mjs`。图片作为整张圆角卡片倾斜和位移，不改变五官、不补绘、不眨眼或张嘴，也不把这种效果称为人物原生立体转头。原 31 款程序化角色的引擎规则继续适用。

1.4.1 采用逐人近景裁切，脸宽约占正方形的 48%～57%。在侧边栏 36 px 大小下逐张检查眼睛、下巴与有辨识度的发饰或手势。照片宿主零内距，圆角 22%，与选图缩略图一致。闲置倾斜为 X +6°、Y −10°、Z −6°，比例 1；悬停中心回到 0° 和比例 1，指针范围内 X / Y 变化不超过 ±6°。移开用 420 ms 过渡回位。工作时边框柔光周期 1.6 秒；完成时整张照片轻弹 640 ms，同一完成事件只触发一次。系统减少动态效果时保持正面静态和稳定状态光。机器可读参数及源码、照片校验值见 `photos/motion-spec.json`。

验收须逐张确认侧边栏和详情显示同一照片、悬停和回位、选择保存和恢复；状态效果的本机演示与真实 Bot 任务分别记录。照片必须保持同一文件内容，不能以面部变形或重绘代替交互。

取景从原片按正方形裁切，再等比例缩到运行时的 256 px。`object-fit: cover` 负责按原比例填满可用面积，眼睛位置、发饰与托腮手势由每张裁切框决定。参见 [MDN 对 cover 的定义](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit#cover)。
